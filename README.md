# book-launch

책 출간 마케팅 계획을 만들어 주는 Claude Code 플러그인입니다. 책과 저자의 상황을 대화로 묻고, 여러 에이전트를 동시에 돌려 진단하고 할 일을 짠 뒤, 처음 책을 내는 사람도 읽을 수 있는 문서 한 편으로 정리합니다.

## 무엇이 나오나

`book-launch/출간-마케팅-계획.md` 한 파일입니다.

- **한 장 요약**: 목표에 닿을 수 있는지, 이번 주 할 일 3가지, 가장 약한 곳, 알려주면 더 정확해지는 값
- **출간 전 점검 10가지**
- **할 일**: 출간 8주 전부터 출간 후까지. 첫 책이면 꼭 할 일 30개 이내
- **출간 후 6주 달력**: 주마다 큰 일 하나와 매일 하는 일
- **예상 비판과 답, 소개 문구 방향**
- **계산 근거**: 모든 숫자에 출처(확실 / 조사함 / 비슷한 사례 / 추측) 표시

## 쓰는 법

```
claude --plugin-dir /path/to/marketing-skill
```

Claude Code를 연 뒤 "책 마케팅 계획 세워줘"라고 말하면 됩니다. 파일을 채울 필요는 없습니다. 묻는 말에 답하면 되고, 모르는 것은 "모르겠음"이라고 하면 됩니다.

첫 질문은 "전에 낸 책의 판매 기록이 있나요?"입니다. 답에 따라 질문 수, 목표, 할 일 분량이 달라집니다.

| | 첫 책 | 판매 기록 있음 |
|---|---|---|
| 기본 목표 | 1쇄 부수를 12주 안에 다 팔기 | 전작 첫 주 판매 넘기 |
| 예상 판매 계산 | 채널 계산과 비슷한 책 조사를 대조 | 전작 기록으로 계산 |
| 할 일 | 꼭 할 일 30개 이내 | 줄기마다 24개까지 |

## 깊이

| 깊이 | 동시에 도는 에이전트 | 이럴 때 |
|---|---|---|
| 빠르게 | 4개 | 대략적인 방향만 볼 때 |
| 기본 | 8개 (판매 기록 있음은 7개) | 보통 |
| 꼼꼼히 | 9~10개 | 경쟁 신간 조사와 독자 관점 검토까지 |

에이전트 수만큼 사용량이 듭니다. 처음에는 "빠르게"로 돌려 보고 필요하면 깊이를 올리세요.

## 내 환경에 맞게 바꾸기

`book-launch/profile.yaml`의 `targets`에서 목표 판매량, 목표 기간, 각종 비율을 바꿀 수 있습니다. 비워 두면 기본값으로 계산하고 결과에 "추측"이라고 표시합니다.

실제 값을 넣을수록 정확해집니다.

- 채널별 최근 게시물 평균 조회수 (`channels[].avg_views`)
- 전작 첫 주 판매와 당시 팔로워 수 (`record`)
- 출간 알림 신청 수, 예약 판매 부수 (`experiment`)

출간 뒤에 주간 판매량을 알려주면 판매가 늘고 있는지 줄고 있는지 실제 값으로 보여 주고, 그 기록을 다음 책의 계산에 씁니다.

## 필요한 것

- Claude Code
- Python 3.9 이상, PyYAML (`pip install pyyaml`)
- 비슷한 책 조사에는 웹 검색 도구

## 폴더

```
.claude-plugin/plugin.json
agents/                      에이전트 6개
skills/book-launch/
  SKILL.md                   진행 순서
  references/                판단 틀, 점검표, 단계, 질문 문구, 쉬운 말 사전
  scripts/calc.py            계산, 검사, 문서 변환
  templates/                 내 책 정보 양식
```

고치기 좋은 곳:

- `references/glossary.md`: 사용자에게 보이는 낱말, 판정 문구, 금지어
- `references/rubric.md`: 힘 6가지를 판정하는 예/아니오 질문. 문구와 기준 숫자는 초안이라 분야에 맞게 고쳐도 됩니다. 힘마다 5개를 유지하고, 순서를 바꾸면 `framework.md`의 번호 참조도 같이 고칩니다.
- `references/intake.md`: 질문 문구와 기본 목표
- `references/phases.md`: 17단계, 할 일 양식, 할 일을 쓸 때 지킬 규칙

계산을 고친 뒤에는 `python skills/book-launch/scripts/calc.py --selftest`로 확인합니다.

## 바탕이 된 것

자청의 출판 마케팅 프롬프트를 분석해 구조를 다시 설계했습니다. 원문 문구는 들어 있지 않습니다. 판매 흐름을 여러 힘의 곱으로 보는 생각, 출간 전 점검, 주마다 큰 일과 매일 하는 일을 나누는 방식은 그 프롬프트에서 왔습니다.

계산에 쓰는 기본 비율은 검증된 통계가 아니라 출발점입니다. 결과는 예측이 아니라 범위와 가정으로 읽어 주세요.

## 알아 둘 한계

- 예상 판매는 내 채널을 거쳐 팔리는 양만 계산합니다. 서점 진열, 출판사 홍보, 입소문으로 팔리는 양은 모릅니다.
- 비슷한 책의 판매 부수는 공개되는 경우가 드물어, 조사가 빈손으로 끝나는 일이 많습니다.
- 할 일은 세 에이전트가 힘 기준으로 나눠 동시에 씁니다(증거와 검색 / 답하기와 팬 모임 / 퍼뜨리기와 연결). 처음에는 시기별로 나눴는데, 같은 줄기의 일이 여러 작성자에게 흩어져 겹치거나 서로 미루는 문제가 나와 바꿨습니다. 그래도 서로의 결과를 못 보기 때문에 줄기를 넘나드는 부분은 마지막 검토에 기댑니다.
- 시험 실행은 가상 저자 두 명(첫 책, 판매 기록 있음)으로 했습니다. 대화로 정보를 받는 부분, 출간까지 8주가 안 남은 경우, 하루 30분인 경우는 실제로 돌려 보지 않았습니다.
